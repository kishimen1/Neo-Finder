# Neo-Finder 0.1 実装・検証状況

更新日：2026年10月9日。自分のMacで日常利用するための初期実装です。ここでの「実装済み」はソースに機能があることを示し、すべての保存先・操作の受入試験に合格したことを意味しません。

## 利用できる機能

| 項目 | 実装内容・範囲 |
|---|---|
| 常時2ペイン | 左右／上下の切替、境界の調整、アクティブな側の明示 |
| 独立タブと履歴 | ペイン別の場所・戻る／進む・表示方法・並び順。最後のタブを閉じるとウインドウを閉じる |
| 作業セット | 左右の状態、分割方向・比率、アクティブ側を自動保存。名前付き保存・読み込み・削除 |
| お気に入り | グループ名を指定して追加、表示名の変更、登録解除。実フォルダ名は変更しない |
| 一覧 | 名前・変更日・サイズ、フォルダ優先の自然順、昇降順、標準ファイルアイコン、タグの読取り表示 |
| 簡易カラム | 現在のフォルダと最大2階層の親を並べる。フォルダ選択で移動 |
| 即時絞り込み | 現在の一覧の名前に適用。大文字小文字、全半角、結合文字、濁点等の比較用正規化。実ファイル名は変更しない |
| 相対日付 | 今日・昨日・数日前等と絶対日時の確認。表示切替 |
| Quick Look・OS連携 | 標準プレビュー、既定アプリで開く、Finderで表示、共有パネル、簡易情報表示 |
| Finderとの受渡し | ファイルURLのコピー＆ペースト、ドラッグ＆ドロップ、フォルダの「Neo-Finderで開く」用アプリ登録・サービス定義 |
| コピー・移動 | 上書きなし。同名は両方残す／スキップ／中止。同一ボリューム内の移動 |
| その他の編集 | 単一項目の名前変更、新規フォルダ、ゴミ箱へ移動 |
| 取消 | 内容・属性・同一性を確認できる操作の逆操作。今回の起動中のみ |
| 操作の表示 | 1ジョブずつ実行、完了・部分成功・失敗、中止、履歴、前回中断の通知 |
| 権限と復元 | 本人が選択したフォルダへのアクセスを保存し、再起動時に復元する仕組み |

通常の一覧読込みは必要なメタデータのみを読み、ファイルの内容やフォルダ全体の容量を読みません。表示中のフォルダはアプリがアクティブな間、約5秒ごとにも再確認します。コピーの検証、取消の確認、明示したプレビューでは内容を読むため、大きな項目では時間がかかります。

フィルターは作業セットの復元時に解除します。選択はタブごとに起動中に記憶し、同じ一覧の更新では選択・スクロール位置を保ちます。選択・スクロール位置を再起動後まで永続化する機能はありません。存在しない保存済みパスを別の場所へ置き換えず、読込み失敗として案内します。

## 編集できる場所と操作の制限

編集を有効にするには「フォルダを登録…」で、その場所がクラウド同期されていないローカルフォルダであることを指定します。アプリはローカルAPFS、既知のiCloud・CloudStorageパス、アクセス範囲を確認します。任意の同期ソフトの設定や、すべてのプロバイダーの同期状態を識別する機能はないため、同期対象の場所を編集用として登録しないでください。

| 操作 | 現在の扱い |
|---|---|
| 同名ファイルの上書き・フォルダ結合 | 行わない。確定時にも既存項目を置き換えない |
| 別ボリューム移動 | 拒否。必要ならコピーを使う |
| 大小文字のみの名前変更 | 拒否してFinderでの操作を案内 |
| シンボリックリンク | 書込みではリンク自体を操作。再帰検証でリンク先の内容をたどらない |
| `.app`等のパッケージ | 一覧では1項目。コピー・取消の確認では配下も対象 |
| ゴミ箱が利用できない場合 | 失敗として停止。永久削除に切り替えない |
| 登録した作業ルート自体の変更 | 移動・名前変更・ゴミ箱は拒否 |
| 中止 | 項目単位で停止。処理中の大きな1項目を即座に中断しない |
| 連続ジョブ | 実行中は次の書込みを受け付けない。待機キューや並べ替えは未実装 |
| 再起動後 | 状態・操作履歴を復元。書込みの自動再実行、Undoの復元はしない |

コピー先の取消では作成した項目をゴミ箱へ移します。移動・名前変更・ゴミ箱の取消では、項目を確認できて元の場所が空いている場合に戻します。フォルダの子孫の追加・変更、属性変更、権限不足などがあれば取消を保留し、成功分と失敗分を分けます。

ゴミ箱移動自体が成功しても、Sandboxの権限等でゴミ箱内を確認できなければ、その項目は取消可能として登録できません。画面の結果を確認し、必要な場合はFinderのゴミ箱で操作します。

## 検証の現在地

**Releaseビルドとローカル署名の検査、統合テスト37件が成功しました。署名したSandboxアプリを起動して、下記の実機確認も実施しました。**

| 対象 | 個別検証済みの内容 |
|---|---|
| モデル・保存：11件 | 左右の履歴分離、前進履歴の切断・上限、Unicode絞り込み、自然順、隠し項目・パッケージ・リンクのメタデータ列挙、存在しない場所、状態の保存・復元、未知バージョンの上書き防止、保存失敗時の既存データ維持、復元時の不正選択修復 |
| ファイル操作：26件 | コピー・同名衝突・部分成功、自己／子孫への転送拒否、壊れたリンク、移動・名称変更と取消、外部変更検知、フォルダ子孫の変更・追加、空フォルダ取消、復元先の衝突、ゴミ箱失敗、中止、操作履歴と再起動、日時・権限・拡張属性。ゴミ箱移動直後の属性更新、移動中の内容・実体変更、実ゴミ箱往復を追加 |

自動テストは一時フォルダ内の使い捨てデータで行います。通常のゴミ箱処理は`trashHandler`を差し替えてテスト領域内へ移動します。追加の実ゴミ箱テスト1件は`NEOFINDER_REAL_TRASH_TEST=1`で有効にし、専用ファイルを実ゴミ箱へ移動してから元へ復元します。最終統合試験ではこの1件も有効にして37件成功しました（実行約0.49秒、ビルド時間は除く）。テスト実行体はアプリのSandboxとは別条件です。

Codexの実行サンドボックス内では`NSFileCoordinator`のOSサービス連携が拒否されるため、テストとReleaseのデバッグ情報生成は通常権限で実行しました。製品側のApp Sandboxは有効のままです。CLT由来の存在しないFramework検索パス警告等は出ますが、ビルドとテストの終了結果は成功です。

### 性能の実測

ローカル一時フォルダの日本語連番名1万ファイル（空／約30バイト交互）、Swift最適化ビルド、macOS 26.6.2、arm64、論理10コア、メモリ24GiBで測定しました。

| 測定 | 結果 |
|---|---|
| `FolderReader.contents`の初回呼出し1回 | 683.88 ms |
| `FileEntry.filtered`、名前昇順、20回の中央値 | 15.114 ms |
| 同p95（nearest-rank） | 15.248 ms |
| 一致項目数 | 各回120件（検索語`099`） |

作成直後のデータでOSキャッシュは除去していません。コアの列挙・絞り込みが設計目標の範囲に入った結果であり、アプリのコールド起動、アイコン生成、画面描画、キー入力の応答時間を含むものではありません。

以下は、別途実機で確認すべき事項です。

- 権限取消・外付け未接続・すべてのエラー表示の組合せ。
- Finderとの相互ドラッグ・コピー＆ペースト、未起動時の外部フォルダ受渡し。
- 実際の日本語IME変換過程、全ショートカット、VoiceOver読み上げ。
- ウインドウの最小サイズでの全配置、カラムの複数選択・ドラッグの網羅的操作。
- アプリの1万項目描画を含む応答、大容量ファイル、実容量不足、強制終了・中断の全条件。

ドラッグの実機自動操作はComputer Use側の`noWindowsAvailable`で実行できず、動作確認済みには含めていません。アプリのドラッグ実装と、転送エンジンのテストはそれぞれ存在します。

## 開発構成・保存場所

| 場所 | 内容 |
|---|---|
| `Sources/NeoFinder/` | AppKitのウインドウ、ペイン、メニュー、Quick Look、権限管理 |
| `Sources/NeoFinderCore/` | メタデータ列挙、状態モデル、保存、ファイル操作エンジン |
| `Tests/NeoFinderCoreTests/` | Swift Testingによるモデル・操作テスト |
| `Resources/` | アプリ情報、Sandboxの権限設定 |
| `scripts/build.sh` | release／debugビルド、`.app`作成、ad hoc署名・署名検査 |
| `scripts/test.sh` | コアテスト。CLT環境に応じてTestingマクロの場所を指定 |
| `dist/Neo-Finder.app` | 起動するアプリ |

Swift 6コンパイラ／Swift 5言語モード、SwiftPM、macOS 26以上、Apple Siliconを対象とします。App Sandboxとユーザーが選択したファイルへのread/write権限を有効にし、security-scoped bookmarkを保存します。ローカル用のad hoc署名で、Developer ID署名・公証・配布インストーラはありません。

作業状態・ブックマーク・操作履歴は、OSが返すApplication Support内の`Neo-Finder/`にJSONで保存します。Sandbox版ではアプリのコンテナ内です。編集を有効にした場所とウインドウ設定はUserDefaultsにも保存します。閲覧するフォルダへ設定用ファイルを作りません。コピー中のみ、転送先に隠し作業ディレクトリを作り、通常終了時に片付けます。

操作履歴は最大300件です。前回の未完了ジョブは通知し、自動で再開しません。状態ファイルの未知バージョンは上書きを拒否し、壊れた操作履歴は記録なしの書込みを開始しません。

`design/`の設計書・調査・HTMLモックは実装前の記録として維持しています。設計上の目標と現在の実装範囲を混同しないよう、本書を現在の状況の入口とします。
