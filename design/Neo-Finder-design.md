# Neo-Finder 設計書

設計日：2026年10月9日 / 状態：初期設計 / 対象：自分のMacでの日常利用

## 1. 提案の中心

**Finderと同じ感覚で操作でき、左右の作業場所と作業途中の状態を覚えているファイルマネジャー**を作る。

Finderの慣れた操作を土台に、OneCommanderの「2つの場所を行き来しやすい」「作業場所を覚えられる」「多数のファイルを見分けやすい」という利点を加える。標準画面は常時2ペインとし、機能を増やしてもファイル一覧を主役にする。

技術上は、Finder本体の改造ではなく、**Finderと併用する独立したネイティブmacOSアプリ**とする。AppleのFinder Syncの公開範囲はバッジ、メニュー、ツールバーボタン等であり、Finder内部を2ペイン化する公開手段は確認できない。この制約からの設計判断である。[Finder Sync](https://developer.apple.com/documentation/FinderSync)

FinderからNeo-Finderへフォルダを渡す導線、およびNeo-Finderから「Finderで表示」を設ける。デスクトップ、ファイルを開く／保存するシステムダイアログ、他アプリのFinder呼び出しを一律に置き換える設計にはしない。

## 2. 設計の前提と調査の読み方

- ユーザー確認済み：まずは本人のMacで日常利用する。
- 実環境の読み取り結果：macOS 26.6.2、arm64。初期検証対象はmacOS 26のApple Silicon機とする。旧OS・Intel・一般配布の対応は別途判断する。
- Windows用 **OneCommander** が参照対象。macOS用の別製品 **Commander One** とは区別する。
- 公式ページで確認した安定版は3.108.0.0（2026-09-26）。v4は公開ベータで、公式も日常の重要作業にはv3を推奨している。[公式](https://www.onecommander.com/) / [v4 beta](https://onecommander.com/beta)
- 公式機能、利用者が実際に評価した点、本設計での提案は区別する。公開レビューは任意の投稿のため、人気順位・利用者全体の支持率とはみなさない。
- Microsoft Storeの指定ページは参照したが、今回の取得ではレビュー本文・件数・星評価を検証できなかった。評価の水増しや推測はしない。

根拠ごとの詳細と限界は[調査根拠](research.md)にまとめる。

## 3. 追加機能の選定

「高評価」は母集団のあるランキングではなく、独立した利用者の肯定的な言及を確認したものを指す。採用優先度には、本人の日常作業への効果、Finderとの差分、実装負担も加味する。

| 候補 | OneCommanderから得る価値 | Finderとの差分・Neo-Finderでの具体化 | 優先度 |
|---|---|---|---|
| 常時2ペイン | コピー元とコピー先を同時に把握 | 1ウインドウ内に独立した左右の一覧。各側でタブ・履歴・表示を保持 | 必須・初期 |
| 永続タブと作業セット | 開いていた場所へ戻りやすい | タブを左右の組で保存。「資料整理」「写真整理」などの名前で復元。単なるタブ追加との差分 | 最優先・初期 |
| グループ別お気に入り | 案件・用途ごとに場所をまとめる | 「仕事」「個人」「写真」等のグループ。表示名変更は元フォルダ名を変えない | 最優先・初期 |
| カラムを使う階層移動 | 深いフォルダの親・兄弟を見失いにくい | Finderのカラムを維持し、左右で独立表示。階層をたどる側と整理先を同時に固定できる | 基本互換・初期 |
| フォルダ内の即時絞り込み | 長い一覧から候補を減らせる | 各ペインに「このフォルダを絞り込む」。通常の文字入力による項目選択とは分ける | 最優先・初期 |
| 相対日付・更新時期の視覚化 | 最近触った項目を見分ける | 「今日・3日前」＋控えめな印。絶対日時も確認可能。Finderタグの色と区別 | 小さな追加・初期 |
| 一括名称変更 | 規則のある整理をまとめて行う | Finderにも一括名称変更はある。追加価値は正規表現、変更前後の一覧、衝突検出、プリセット、条件付き取消 | 第2段階 |
| 操作キュー・履歴 | 複数の転送状況をまとめて把握 | 常設できる操作棚。実行対象・転送先・部分成功・取消可能範囲を明示 | 最小履歴は初期、拡張キューは第2段階 |
| 柔軟な一覧・プレビュー | 種類に応じた情報を表示 | Quick LookはmacOS標準を利用。PDF・写真の追加情報、表示設定の保存を段階導入 | 標準プレビューは初期、拡張は後続 |
| フォルダ容量 | 大きいフォルダを見つける | 明示操作でバックグラウンド計算。表示のたびに再帰計算しない | 第2段階以降 |

タブ・カラム・Quick Look・タグ・基本検索・一括名称変更を「Finderにない新機能」と説明しない。Finderにもある機能は、使い慣れた基盤として残す。[Finderの表示と整理](https://support.apple.com/ja-jp/guide/mac-help/mchle9f0a1b2/27/mac/27) / [macOS 26の名称変更](https://support.apple.com/ja-jp/guide/mac-help/mchlp1144/26/mac/26) / [Quick Look](https://support.apple.com/ja-jp/guide/mac-help/mh14119/26/mac/26)

### 初期に取り込まないもの

To-Do、フォルダ内メモ、画像一括変換、任意スクリプト、複雑なテーマ編集は保留する。機能の存在は確認できても、本人の用途で優先すべき根拠が弱い。フォルダ比較・自動同期・重複削除も、OneCommanderの人気機能として一括りにせず別テーマとする。

WindowsのEverythingやNTFS固有検索をmacOSへ移植する前提にはしない。macOSではSpotlightを活用する。v4の検索やTaskmaster強化は将来の参考にし、安定版で長く評価された機能と混ぜない。

## 4. Finder操作を守る契約

「操作性をそのまま」は、最初に日常操作を一致させる要件として扱う。Finderの全機能・全拡張メニューの完全互換を約束する意味ではない。

| 操作 | Neo-Finderの挙動 |
|---|---|
| クリック、ダブルクリック | 選択、開く。単一クリックで開くWindows式へ変更しない |
| Return | 名前変更。Enterでファイルを開く挙動にしない |
| Space / ⌘Y | 選択項目をQuick Look。閉じると一覧の選択・フォーカスを戻す |
| ⌘O / ⌘↓、⌘↑ | 開く、親フォルダへ移動 |
| ⌘[ / ⌘] | アクティブなタブで戻る／進む |
| ⌘C → ⌘V | コピーして現在のペインに貼り付ける |
| ⌘C → ⌥⌘V | 元の場所から現在のペインへ移動する |
| ⌘Delete | ゴミ箱に入れる。通常のDeleteを永久削除にしない |
| ⌘Z | 直前の取消可能な操作を戻す。テキスト編集中は編集のUndoを優先 |
| ⇧⌘N、⇧⌘G | 新規フォルダ、フォルダへ移動 |
| ⌘T / ⌘W | アクティブペインのタブを作成／閉じる。最後のタブならウインドウを閉じる。次回は左右を復元する |
| ⌘1〜4 | アイコン・リスト・カラム・ギャラリー。実装済み表示だけを有効にし、別機能に転用しない |
| ⌘F | Spotlightの範囲検索。フォルダ内フィルターとは分ける |
| ⇧⌘. / ⌘I | 隠し項目の表示切替、選択項目の情報。未実装機能を別の意味で上書きしない |
| ⌘クリック / ⇧クリック / 矢印 | 複数選択・範囲選択・項目移動。日本語IME入力を妨げない |
| 通常のファイル一覧で文字入力 | Finder同様の名前による選択。絞り込みは専用欄で行う |
| ドラッグ＆ドロップ | 同じボリュームは移動、別ボリュームはコピーを基本に、Optionでコピー、必要な場面でCommandで移動。実際の種別をカーソルと転送先で表示 |

基準は[Appleのキーボードショートカット](https://support.apple.com/ja-jp/102650)、[ショートカット概要](https://support.apple.com/ja-jp/guide/mac-help/mchld6b9e240/26/mac/26)、[名称変更](https://support.apple.com/ja-jp/guide/mac-help/mchlp1144/26/mac/26)。実装時に対象OSのFinderと並べて照合する。「常時分割」は開いているウインドウ内での要件であり、ウインドウを閉じる操作を妨げない。⌘Wの対象はメニュー上で「タブを閉じる／ウインドウを閉じる」と明示する。

**2ペインの原則**：選択は両側に残せるが、コマンド対象はフォーカスのある側だけ。「右へコピー」「左へコピー」は追加の明示操作として提供し、通常の貼り付けの意味を変えない。実行時点の転送先を固定し、実行途中で別のタブを開いても転送先を変更しない。

新しいショートカットは標準操作・IME・VoiceOverとの衝突を確認してから割り当てる。初期はメニューとボタンで提供し、F5/F6やCtrl+XなどWindowsの慣習を既定として持ち込まない。

Finderとの相互ドラッグ、ファイルURLのコピー＆ペースト、既定アプリで開くことも互換の範囲に含める。タグはmacOSの標準メタデータを利用し、独自タグへ移行させない。標準共有はOSの提供範囲で統合する。圧縮・クイックアクション・サーバ接続・拡張機能固有の右クリック項目等は段階導入またはFinderへの導線で補い、初期版の機能一覧で未対応を明示する。

## 5. 画面構成

```text
┌ Neo-Finder     作業セット：資料整理          表示・検索・設定 ┐
│ よく使う項目 │ ［ダウンロード］［書類］    │ ［整理先］［資料］ │
│   書類       │ 戻る 進む  パス             │ 戻る 進む  パス    │
│   ダウンロード│ このフォルダを絞り込む      │ 絞り込む            │
│              │ 名前          更新日  サイズ│ 名前  更新日 サイズ │
│ 仕事         │ 報告書.pdf    今日     2 MB │ …                   │
│   資料       │ 予算.xlsx     3日前  240 KB │                     │
│ 個人         │                             │                     │
│   写真       │ 2件選択          右へコピー │                     │
├──────────────┴─────────────────────────────┴─────────────────────┤
│ 操作：2項目を整理先へコピー中     1/2     中止   履歴を表示        │
└─────────────────────────────────────────────────────────────────┘
```

- サイドバーは共通、タブ・パス・表示方式・選択・スクロール位置はペイン別。
- 左右の境界はドラッグで調整。初期比率50:50。片側を狭めても自動的に閉じない。
- 狭いウインドウでは上下2ペインを選択できる。2ペイン維持を既定とし、集中用1ペインは明示切替のみ。元の状態へ戻れる。
- 標準フォント、OSのアクセントカラー、ライト／ダーク、標準メニュー、自然な右クリックを使う。独自装飾のために行間や余白を広げすぎない。
- アクティブペインは見出しとフォーカス枠で示す。非アクティブ側の選択は落ち着いた色にする。色だけに意味を依存させない。
- 名前を優先し、狭いときはサイズ等の補助列を整理する。長い日本語名は省略と全文表示を両立。
- 常設プレビューは任意。開いた結果2ペインが消えるなら、フローティングのQuick Lookを優先。
- 空フォルダ、絞り込み0件、読込中、権限なし、接続切れをそれぞれ別表示にする。

### 作業セット

「左右のタブ・各タブの場所・表示形式・並び順・左右比率・アクティブ側」を名前付きで保存する。既定セットは前回状態を自動保存、名前付きセットは明示的に上書き保存する。履歴・選択・スクロール位置は可能な範囲で復元するが、削除済み項目は復元しない。

一時的なフィルターは既定では解除して復元する。絞り込みで項目が見えないことを避けるためであり、保存したい場合のみセット設定で指定する。保存先が外付けで未接続なら元のパスと「接続待ち」を表示し、別フォルダへ黙って差し替えない。

お気に入りは場所へのリンク、作業セットは画面全体の状態。両者を区別し、セット切替やお気に入り削除で実ファイルを変更しない。

## 6. 初期版の利用シナリオ

### ダウンロードを整理する

1. 「資料整理」セットを開き、左にダウンロード、右に整理先を復元する。
2. 左の専用欄で「請求書」を絞り込み、Spaceで内容を確認する。
3. 複数項目を選び「右へコピー」。ボタン付近に転送先フォルダ名と件数を表示する。
4. 同名項目がなければ開始。同名なら「両方残す／スキップ／中止」を選ぶ。初期版では上書きしない。
5. 操作棚から進捗・完了・失敗を確認する。必要なら今回のコピーを取り消す。

### 深い階層の資料を集める

左をカラム、右をリストにする。左で親・兄弟フォルダを見ながら資料を探し、右の整理先はそのまま保つ。フォルダを切り替えても両ペインの表示方式をそろえる必要はない。

### 規則に従って名前を整える（第2段階）

複数選択から名称変更を開く。最初は「置換・連番・日付」、詳細欄を開いた場合だけ正規表現を使う。元名と新名を並べ、重複・空名・使用できない名前を実行前に検出する。途中失敗は成功分と失敗分を残し、「全部元に戻った」と表示しない。

## 7. 機能仕様の要点

### 表示と検索

現在フォルダの絞り込みは既に列挙した名前に適用し、サブフォルダ内までは検索しない。日本語の合成文字・全半角などは検索用の比較キーで扱い、実ファイル名を書き換えない。絞り込み中は件数と解除ボタンを常に見せる。隠れた選択項目は操作対象から外し、処理件数を見た目と一致させる。

Spotlight検索には「このフォルダ以下／アクセス可能な場所」の範囲を表示する。未索引・検索除外・権限不足を含む全領域を網羅したとは表示しない。必要時に限定的なファイル名走査を選べるようにする。[NSMetadataQuery](https://developer.apple.com/documentation/foundation/nsmetadataquery)

更新時期の表示は最終変更日時から計算する。「今日」「昨日」「3日前」等はローカル時刻で日付境界を扱い、ツールチップまたは情報欄に正確な日時を出す。最近の更新を「重要」「最新版」と推測しない。日付の色とFinderタグの丸印は位置と形を分ける。

### 操作棚と取り消し

すべての書込み操作を1つの操作サービスに集約する。画面イベントからファイルを直接変更しない。操作棚には元の場所・転送先・対象数・処理済み数・失敗理由を残す。初期版の並列書込みは1ジョブ、ほかは待機。閲覧は継続可能とする。

状態は `準備 → 待機 → 実行中 → 完了 / 部分成功 / 中止 / 失敗`。取消操作は元ジョブと関連づけた別ジョブとして記録する。中止は「これ以上進めない」であり、既に完了したコピーの自動削除を意味しない。ファイル単位で安全に止める方式を初期とし、止まる単位・処理中項目を表示する。APIで取得できない精密な進捗や残り時間を推測で埋めない。

| 操作 | 初期版の取消条件 |
|---|---|
| 新規コピー | 作成先が外部変更されていなければコピー先だけをゴミ箱へ。フォルダは子孫の追加・削除・内容変更も確認し、確認できなければ取消を保留。元ファイルは触らない |
| 名称変更・同一ボリューム移動 | 同じ項目と確認でき、元の名前・場所が空いている場合だけ逆操作 |
| 新規フォルダ | 自分が作成した空フォルダのときのみ取消 |
| ゴミ箱へ移動 | 返却されたゴミ箱内URLを記録し、実体と復元権限が残り元の場所へ戻せる場合のみ復元。返却URLだけで復元権限が保証されるとは扱わない |
| 上書き・フォルダ結合 | 初期版には含めない。後続でも復元用退避を検証するまでUndoを約束しない |

`UndoManager`は逆操作の登録先であり、ファイル操作を自動復旧するエンジンではない。[UndoManager](https://developer.apple.com/documentation/foundation/undomanager) / [trashItem](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:))

初期版のUndoはアプリ起動中の履歴に限定する。再起動後は台帳で途中状態を提示し、自動の再開・再実行・Undoは行わない。失敗分の再試行も存在・権限・同名衝突を再検証する。

### データを扱う境界

コピー元と先の同一性、自分自身の下へのフォルダ移動、大小文字のみの変更、日本語名、symlink、パッケージを明示的に扱う。シンボリックリンクは既定でリンク自体を操作し、再帰先を暗黙にたどらない。`.app`等は通常1項目として表示する。

別ボリューム移動はコピーと元の削除の組合せになる。初期版では無効としてコピーを案内し、後続で「コピー完了と元項目の不変確認後に削除」を検証する。途中失敗でも元ファイルを残す。同名ファイルへの書込みは、事前確認だけでなく確定時にも排他的に検査する。

OS標準APIを使っても、タグ・拡張属性・ACL・resource fork等の保持は実ファイルで確認する。保証できない保存先では制限を表示する。ゴミ箱が利用できなければ失敗として止め、永久削除へ切り替えない。

## 8. macOSとの統合と技術構成

### 採用案

**Swift + AppKitをファイル操作UIの中心とし、設定・補助パネルにSwiftUIを使う。** 2ペイン、表、複数選択、ドラッグ、メニュー、レスポンダチェーンをmacOSに合わせて制御するため。HTMLモックは画面検討用であり、製品をWebViewで実装する方針ではない。

| 層 | 責務・候補 |
|---|---|
| ウインドウ・表示 | `NSSplitViewController`、`NSTableView` / `NSOutlineView`、カラム用AppKitビュー。アイコン・ギャラリーは後続の`NSCollectionView`等 |
| 状態管理 | Window → Workspace → Pane → Tab。アクティブ側と選択側を明示し、片側の状態変更をもう片側へ伝播させない |
| フォルダ読込 | バックグラウンド列挙、必要なメタデータのまとめ取得、キャンセル、表示行の再利用。OS変更通知を手掛かりに再照合 |
| プレビュー | `QLPreviewPanel`、必要時`QLPreviewView`。システム提供形式の範囲で利用し、独自のOffice/PDF変換器を作らない |
| 検索 | 現在フォルダのメモリ内絞り込み、`NSMetadataQuery`によるSpotlight検索 |
| 操作 | FileOperationService、`FileManager`、必要箇所の`NSFileCoordinator`、台帳、逆操作。I/Oはメインスレッド外 |
| OS連携 | `NSWorkspace`で既定アプリを開く／Finderで表示、標準共有UI、ファイルURLのpasteboardとdrag対応 |
| 保存 | 作業セット・お気に入りはversion付きCodable、操作台帳はSQLite等の確実に更新できるローカル保存。内容プレビューは原則永続化しない |

API根拠：[NSSplitViewController](https://developer.apple.com/documentation/appkit/nssplitviewcontroller) / [NSViewRepresentable](https://developer.apple.com/documentation/swiftui/nsviewrepresentable) / [QLPreviewPanel](https://developer.apple.com/documentation/quicklookui/qlpreviewpanel) / [NSFileCoordinator](https://developer.apple.com/documentation/foundation/nsfilecoordinator)

`NSFileCoordinator`は他プロセス等とのアクセスを調整するAPIで、複数ファイル操作の原子的なトランザクションや自動Undoを提供するものではない。転送中の再起動も含めた台帳管理は別途必要。

### 権限と保存

初期はApp Sandboxを有効にし、本人が選択したフォルダへのread/write権限とsecurity-scoped bookmarkを用いる案を採用する。対象を個人用に絞り、最初からディスク全体の走査権限を要求しない。広域アクセスやサービス連携が支障になる場合は技術検証後に非Sandbox版を比較するが、TCCによる保護を回避する設計にはしない。

bookmarkはURLの文字列保存とは別。解決時の失効を検出し、アクセス開始と終了を対応させる。初回に本人が主要ルートを複数登録できるようにして、階層移動のたびの許可要求を避ける。許可ルートの外にある親や別の場所へ移動するときは追加選択を案内する。権限が消えたら対象だけ再選択を案内する。ユーザー設定と履歴はアプリのApplication Supportに保存し、元フォルダへ管理ファイルを勝手に作らない。[AppleのSandboxファイルアクセス](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)

### クラウド・ネットワーク

iCloud Drive、OneDrive、SMBを「普通のフォルダだから完全対応」と扱わない。内容がローカルにないファイルは読出しでダウンロードが発生し得る。一覧表示では内容を読まず、プレビュー・ハッシュ・容量算出は明示操作で行う。汎用APIで判定できないプロバイダー状態は「状態不明」とし、同期済みの印を捏造しない。[Apple TN3150](https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files)

初期版の書込み保証対象は検証済みのローカルAPFSのうち、クラウド同期対象でない登録ルートに限定する。APFS上にもiCloud/OneDrive領域はあるため、ファイルシステム種別だけでは判断しない。同期対象やプロバイダー状態を判定できないルートは初期版の書込み対象に加えない。クラウド・SMB・外部形式は段階的に適合試験を行い、未対応の操作では「Finderで開く」を案内する。別アプリの同期バッジ・コンテキストメニュー、Quick Look内編集、Finderスマートフォルダをそのまま継承できるとは約束しない。

### 状態モデル案

```text
Workspace: id, name, schemaVersion, layout, dividerRatio, activePane, panes[]
Pane: id, tabs[], activeTabID
Tab: id, folderBookmark, displayPath, viewMode, sort, history, scrollAnchor
FavoriteGroup: id, name, favorites[{id, alias, folderBookmark}]
FileItem: URL, resourceID?, volumeID?, name, type, size?, modifiedAt?, tags?, availability
Operation: id, kind, sourceRefs[], fixedDestination, conflictPolicy, state, items[], undoRef?
OperationItem: sourceIdentity, plannedDestination, resultURL?, state, error?, before/afterMetadata
```

resourceIDがない保存先もあるため、IDだけを永続的・全環境で一意と仮定しない。項目を再確認できなければUndoを保留する。フォルダ更新は世代番号で古い非同期応答を破棄し、別タブの内容が遅れて表示されないようにする。

## 9. 開発の順序と完了条件

| 段階 | 作るもの | この段階を終える条件 |
|---|---|---|
| 設計（今回） | 機能比較、操作契約、画面モック、技術案 | 出典と提案を分離し、モックの主要操作を確認 |
| 技術検証 | 2ペイン一覧、Sandbox/bookmark、Quick Look、ローカル操作の試験 | 再起動後アクセス、親への権限境界、一覧選択、copy/rename/trash/undoが使い捨てデータで成立。特にゴミ箱からの復元権限を同一起動中に検証 |
| 初期実用版 | リスト/カラム、独立タブ、作業セット、お気に入り、絞り込み、相対日付、標準プレビュー、上書きしない操作と履歴 | 下記のローカル受入試験に合格。全Finder互換とは呼ばない |
| 日常利用の拡張 | アイコン/ギャラリー、Spotlight、タグ編集、簡易＋高度な一括名称変更、追加キュー操作、容量計算 | 本人の代表フォルダで操作・性能を確認し、使わない機能を常時表示しない |
| 保存先の拡張 | iCloud/OneDrive/SMB/外付けの検証、別ボリューム移動、条件付き上書き | 保存先・操作別の適合表ができてから書込み機能を解放 |

工期の確約は置かない。特にクラウドと取消は画面実装より検証負担が大きい。最初に「左右を開く → コピー → 確認 → 取り消す → 再起動して作業場所へ戻る」を縦につなぎ、その後に機能を広げる。

### 初期実用版の受入試験

| 観点 | 合格条件 |
|---|---|
| 常時分割 | 起動・終了・復元・狭幅・表示切替を繰り返しても、意図せず片側が消えない |
| Finderとの操作一致 | Return、Space、開く、親、履歴、コピー、移動、ゴミ箱、IMEの代表操作が契約通り |
| Finderとの相互運用 | Finderから／Finderへのドラッグ・コピー＆ペースト、既定アプリでのオープン、名前と更新日時・タグの保持を検証 |
| 状態分離 | 左右の選択と履歴が混ざらず、実行後にタブを切り替えても転送先が変わらない |
| 復元 | タブの場所・表示・比率を復元。存在しない場所、未接続、権限取消も理解できる表示 |
| コピー | 0バイト、通常文書、多数ファイル、フォルダ、同名、日本語名、パッケージ、リンクを確認。テスト用ハッシュと属性比較で内容・必要メタデータの保持を検査 |
| 失敗 | 容量不足、権限拒否、中止、元ファイル変更でデータを消さず、部分成功を明示 |
| Undo | 通常成功だけでなく、コピー先の外部変更・元パス衝突・ゴミ箱消去時に無理に戻さない |
| フィルター | IME変換中に候補が暴れず、0件と空フォルダを区別。見えていない項目を操作しない |
| アクセシビリティ | キーボードだけで左右とメニューへ移動でき、VoiceOverがペイン名・選択・転送状態を読める |
| 性能 | 同じMacのローカル10,000項目・プレビュー無効で計測。初回一覧1秒程度、絞り込みp95 100ms以内、長いI/O中も操作可能を目標とする。未達なら条件と数値を記録して見直す |

性能数値は設計目標であり、実測値ではない。OS、ハードウェア、ファイル数、コールド／ウォーム、メディア種類を記録して判定する。

## 10. 今回の成果物と残る検証

[画面プロトタイプ](neo-finder-prototype.html)は、分割・独立した場所・作業セット・絞り込み・プレビュー・コピーと取消の流れを試すためのもの。実データの読出し、Finder連携、macOSの権限、Quick Look、同期状態の取得は行わない。
